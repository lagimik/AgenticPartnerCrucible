# Cloud and AI Platform

## What's new?

* 🏢 A federated agent factory governs AI agents across business-unit tenants
* 🧱 Agent execution boundaries get compared across OpenSandbox, AKS, and ACA Sandboxes
* 🐘 A Postgres MCP Server gives coding agents live, permission-scoped database context
* 🏗️ Terraform now deploys Foundry hosted agents via AzAPI data-plane bridging

## Deep links

* [Build and govern AI agents across a multitenant organization](https://techcommunity.microsoft.com/blog/azurearchitectureblog/build-and-govern-ai-agents-across-a-multitenant-organization/4559921): A federated agent factory reference architecture uses the Agent 365 control plane, APIM AI Gateway, and Entra Agent ID/Tenant Governance to let business units run and govern their own AI agents without losing organization-wide oversight. (Microsoft Azure Architecture Blog)
* [When AI Starts Taking Action: Building Execution Boundaries with OpenSandbox and AKS](https://techcommunity.microsoft.com/blog/azuredevcommunityblog/when-ai-starts-taking-action-building-execution-boundaries-with-opensandbox-and-/4561601): A practitioner comparison of MCP, OpenSandbox, and Kata Containers — and of OpenSandbox-on-AKS versus Azure Container Apps Sandboxes and Dynamic Sessions — gives partners concrete tradeoffs for containing agent code and tool execution. (Microsoft Developer Community Blog)
* [Postgres MCP Server: Connect AI coding agents to PostgreSQL](https://techcommunity.microsoft.com/blog/adforpostgresql/postgres-mcp-server-connect-ai-coding-agents-to-postgresql/4561273): The open-source Rust MCP server gives coding agents live, permission-scoped schema, query, and performance context directly from a PostgreSQL database rather than stale documentation. (Microsoft Blog for PostgreSQL)
* [Deploying hosted agents in Foundry Agent Service via Terraform](https://techcommunity.microsoft.com/blog/azure-ai-foundry-blog/deploying-hosted-agents-in-foundry-agent-service-via-terraform/4560435): A Terraform/AzAPI (`azapi_data_plane_resource`) pattern bridges ARM control-plane provisioning with the Foundry data plane, separating Day-1 platform setup from Day-n app-team agent deployment. (Microsoft Foundry Blog)
