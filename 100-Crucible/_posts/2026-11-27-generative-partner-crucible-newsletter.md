## Deep links

* [Foundry Agentic Loop](https://github.com/aiappsgbb/agentic-loop/blob/123d5d2d303d64f3b6725416d290ee990f1bbeae/README.md): Structure workshops and Specify-Implement-Verify-Deploy gates around the reviewed README. Actual builds need Azure authentication, appropriate permissions and approved capacity; separately authorize billable deployment. The portal/plugin were not tested, a pilot is not production acceptance, and the SDK-based runtime differs from the managed Copilot harness. (Agentic Loop GitHub repository)
* [Art of Play in the Age of AI](https://github.blog/news-insights/company-news/art-of-play-in-the-age-of-ai/): Use small, time-boxed experiments for developer skilling, with approved inputs, inspected output and an observable result. Keep prototype success separate from customer delivery evidence and respect open-source contribution guidelines; the article's anecdotes are not a measured productivity or ROI study. (GitHub Blog)
* [Azure Local: 10 mistakes that can derail your deployment before it starts](https://techcommunity.microsoft.com/blog/AzureInfrastructureBlog/azure-local-10-mistakes-that-can-derail-your-deployment-before-it-starts/4569922): Build a pre-procurement readiness gate covering hardware fit, landing-zone placement, DNS/network prerequisites, representative rehearsal and operations handover. Recheck current support matrices, VM-specific recovery and release-specific networking previews; source price examples and engagement outcomes are not current quotes or customer guarantees. (Microsoft Community Hub)
* [Azure Local: 10 anti-patterns that quietly break a running cluster](https://techcommunity.microsoft.com/blog/azureinfrastructureblog/azure-local-10-anti-patterns-that-quietly-break-a-running-cluster/4577143): Package a Day-2 review around workload recovery, independent backup dependencies, physical capacity, change windows and actionable telemetry. Distinguish S2D from SAN checks and VM lifecycle owners; a green cluster/update does not prove user-flow health, and disabling security controls is not a blanket performance fix. (Microsoft Community Hub)
* [Architecture and governance for AI](https://learn.microsoft.com/en-us/azure/cloud-adoption-framework/ai/ready): Extend existing Azure landing-zone governance for approved AI services rather than default to an AI-only hierarchy. Separate platform and workload responsibilities and plan secondary-region models, capacity and retrieval data. Deployment-time model policies are not per-request controls, while network DDoS protection does not replace application-layer protection or recovery evidence. (Microsoft Learn)
* [Generally Available: Model router now supports the Responses API protocol in Microsoft Foundry](https://azure.microsoft.com/en-us/updates?id=581393): Add deployment-based Responses routing while testing model, tool, parameter and continuation compatibility. Deployment-free Auto and per-request routing controls remain preview; protocol GA does not guarantee every backend supports the same features. (Microsoft Azure Updates)
* [Public Preview: Use your model deployments with model router in Microsoft Foundry](https://azure.microsoft.com/en-us/updates?id=581388): Assess eligible same-resource PTU and pay-as-you-go capacity using exact model/version and Data Zone requirements. Routing fees remain additional to capacity/usage charges; the answering model's name does not prove which capacity served the request or establish PTU utilization. (Microsoft Azure Updates)
* [Public Preview: Use model router with AI Gateway](https://azure.microsoft.com/en-us/updates?id=581398): Pilot model ranking behind aliases with explicit priorities, weights and shared API formats. Dedicated AI Gateway differs from APIM service capabilities; supported-model restrictions and continuation behavior matter. Selection has no router fee during preview, but gateway/backend charges remain and preview terms do not promise production readiness. (Microsoft Azure Updates)
* [Generally Available: Agent insights in Microsoft Foundry](https://azure.microsoft.com/en-us/updates?id=581363): Prioritize recurring trace patterns using supported regions, Application Insights, judge-model capacity and authorized telemetry access. AI-generated findings need review; GA insights do not make the separate optimizer workflow GA. Candidate evaluations can invoke live tools before promotion, so isolate actual resources and permissions, not just compute. (Microsoft Azure Updates)
* [Unlocking Data Value with Fabric and Microsoft AI Agents: Choose, Deploy, Optimise](https://techcommunity.microsoft.com/blog/analyticsonazure/unlocking-data-value-with-fabric-and-microsoft-ai-agents-choose-deploy-optimise/4574895): Part 1 covers platform choice, not completed deployment or optimization walkthroughs. Keep core data-agent GA separate from integration previews, and verify capacity, licensing and data movement. Studio Maker authentication uses maker permissions; read-only analytics do not authorize downstream actions, and the legacy Foundry Fabric tool is already unsupported. (Microsoft Community Hub)
