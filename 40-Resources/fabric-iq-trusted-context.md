# Fabric IQ Trusted Context Across Agents and Applications

## Source Summary

The [November 18 announcement](https://community.fabric.microsoft.com/blog/fbc_fabricupdatesblogs/bringing-trusted-fabric-iq-context-to-wherever-people-and-agents-work/5423049)
extends shared business context across Microsoft and third-party experiences.
Its HTML returned 403; the complete publisher RSS description was reviewed.
Fabric IQ joins OneLake data, Power BI metrics, and ontologies describing
entities, relationships, and rules; data and operations agents consume the context.

| Experience or capability | Announced availability |
| --- | --- |
| Power BI semantic models in Copilot; Fabric IQ MCP | GA |
| Fabric data agents in Copilot | GA coming soon |
| ChatGPT and Claude plugins | Preview coming soon |
| Excel context and live connected PivotTables | Insiders Beta |
| Fabric Apps | GA; Copilot app creation and embedded conversational experiences have separate preview/coming-soon scope |
| Ontology access in GitHub Copilot | Preview |
| Semantic views; richer ontologies; sharing; agent setup/governance | Preview or preview coming soon, per feature |
| Faster data-agent answers, larger result sets, time-relative questions | GA; not GA for every agent enhancement |

The Foundry IQ integration section has a GA heading but explicitly labels
**semantic models, shortcuts, and mirrored items as knowledge sources preview**.
Use the detailed item scope rather than treating the entire section as GA.
The [current overview](https://learn.microsoft.com/en-us/fabric/iq/overview)
still labels the IQ workload and ontology preview; ontologies cannot yet be
created from semantic models generated by semantic views.

## Access and Delivery Boundaries

[Copilot guidance](https://learn.microsoft.com/en-us/fabric/iq/connectors/microsoft-365-copilot-overview)
requires Copilot Premium and licensed Power BI access. Existing user permissions,
RLS/OLS, sensitivity labels, and DLP apply. Tenant settings separately govern
Fabric exposure, proactive metadata sharing, and cross-geography processing.
US/EU processing can require explicit cross-geography enablement.
Attaching a report does not constrain the answer to that report alone.

The announcement describes permission-preserving OneLake access, not universal
permission equivalence across every connector. MCP compatibility is not license,
tenant enablement, source access, or write authority.

## Partner Application

**Interpretation:** Start with an owned semantic model and a small set of shared
business definitions. Test answers, source selection, freshness, denied access,
and cross-geography rules separately for each consumer. Treat ontology-agent
changes as proposals for domain-owner review, not silently accepted business logic.
