# Cloud and AI Platform

## What's new?

* ⚙️ Foundry previews the Microsoft Copilot harness for managed prompt-agent execution
* 💰 Claude cost allocation adds Foundry resource and model-level visibility
* 🧪 Project Osmos previews persistent, evidence-validated data engineering
* 🧰 Fabric Assessment Tool turns source-estate discovery into migration evidence
* 📈 Fabric capacity guidance separates admission control, paid relief, and observability
* 🗂️ Direct Lake design choices require explicit security and fallback tests
* 🧭 OneLake Govern reaches GA while Policies Center remains preview

## Deep links

* [Microsoft Copilot harness in Foundry](https://devblogs.microsoft.com/foundry/microsoft-copilot-harness-in-foundry/): Evaluate public-preview prompt-agent execution with managed skills, tools, files, and delegation; hosted-agent long-running resilience is separately GA and still needs application checkpointing and duplicate-action prevention. Harness runtime billing is scheduled for December 1, 2026, while model inference and separately billed services remain chargeable before then. (Microsoft Foundry Blog)
* [Claude cost management and tagging in Microsoft Foundry](https://azure.microsoft.com/en-us/updates?id=577260): GA resource attribution, deployment/resource tags, and model and usage\_type dimensions support showback and chargeback; reconcile customer billing records before promising allocation accuracy, historical backfill, or savings, and do not treat tagging as a spending cap. (Microsoft Azure Updates)
* [Fabric data engineering agent overview](https://learn.microsoft.com/en-us/fabric/data-engineering/data-engineering-agent-overview): Pilot Project Osmos in nonproduction with persistent Spark execution and validation, eligible nontrial capacity, Contributor access, and required tenant settings; the selected lakehouse is a default context rather than an access boundary, and model, validation, and retry consumption need explicit review. (Microsoft Learn)
* [Fabric Assessment Tool](https://github.com/microsoft/fabric-toolbox/tree/main/tools/fabric-assessment-tool): Inventory Synapse and Databricks assets into JSON and offline visualizations to scope migration waves; reconcile permission-limited inventories with platform owners and separately approve optional SQL statistics collection that creates a view. (Microsoft GitHub)
* [Surge protection in Microsoft Fabric](https://learn.microsoft.com/en-us/fabric/enterprise/surge-protection?tabs=onelake-catalog): Design admission and recovery policies around rejection of new work rather than cancellation of running jobs; workspace-level protection is preview, and conflicting mission-critical exemption statements require verification before customer commitments. (Microsoft Learn)
* [Fabric capacity overage overview](https://learn.microsoft.com/en-us/fabric/enterprise/capacity-overage-overview): Evaluate temporary throttling relief at the documented three-times-PAYG rate without assuming additional compute or memory; rolling thresholds are not hard spending caps, so inspect actual enablement and correlate capacity-summary and operation-level telemetry. (Microsoft Learn)
* [Direct Lake overview](https://learn.microsoft.com/en-us/fabric/fundamentals/direct-lake-overview): Compare OneLake and SQL variants using representative security, concurrency, layout, and capacity tests; metadata framing is not an Import refresh, SQL-endpoint RLS does not protect direct OneLake file reads, and fallback behavior differs between variants. (Microsoft Learn)
* [Govern your Microsoft Fabric data estate from one place with the OneLake catalog](https://community.fabric.microsoft.com/blog/fbc_fabricupdatesblogs/govern-your-microsoft-fabric-data-estate-from-one-place-with-the-onelake-catalog/5377369): Use the GA Govern experience and Health, Protect, and Trust skills to structure evidence-led assessments and owner-approved remediation; Policies Center remains preview, permissions still apply, and missing signals are not proof of healthy governance. (Microsoft Fabric Updates)

# AI Business Solutions

## What's new?

* 🧮 Copilot finance workflows span Frontier accounting, GA skills, and plugin rollout
* 🔄 Copilot Studio adopts the Microsoft Copilot harness name without changing existing agents
* 🤝 Dynamics 365 Sales MCP reaches GA for governed CRM actions

## Deep links

* [Microsoft Copilot for finance: Purpose-built for the way finance teams work](https://www.microsoft.com/en-us/copilot/blog/2026/10/29/microsoft-copilot-for-finance-purpose-built-for-the-way-finance-teams-work/): Build bounded reconciliation, close, and forecasting pilots across Excel and Cowork; accounting capabilities are Frontier, Excel finance skills and Cowork Finance/Capital Markets plugins are GA, and ERP and partner plugins are beginning rollout. Preserve professional review, integration prerequisites, and the distinction from the older standalone Copilot for Finance preview. (Microsoft Copilot Blog)
* [The GitHub Copilot harness in Copilot Studio is now the Microsoft Copilot harness](https://www.microsoft.com/en-us/copilot/blog/copilot-studio/the-github-copilot-harness-in-copilot-studio-is-now-the-microsoft-copilot-harness/): Refresh architecture and training terminology without treating the rename as a migration requirement or a change to existing agents, capabilities, or billing; Foundry's separate harness preview does not establish a shared lifecycle or consumption model across products. (Microsoft Copilot Blog)
* [Dynamics 365 CX MCP Server - Sales](https://www.microsoft.com/en-us/dynamics-365/blog/it-professional/2026/10/29/dynamics-365-cx-mcp-server-sales/): The GA server exposes 59 governed tools for opportunity, lead, account, activity, pricing, quote, and order workflows through supported AI experiences; validate client support and connections through Agent 365 Tooling Gateway, preserve Dataverse roles and permissions, and define approval boundaries for consequential actions. (Microsoft Dynamics 365 Blog)
